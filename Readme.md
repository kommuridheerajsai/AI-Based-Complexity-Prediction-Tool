#  AI-Based Complexity Prediction Tool
## Project Overview

The **AI-Based Complexity Prediction Tool** is a machine-learning project that estimates the time-complexity category of Python code using extracted structural features.

The application uses a Random Forest classifier to predict categories such as Constant, Logarithmic, Linear, and Quadratic. A Streamlit web interface allows users to enter Python code and view the predicted category and extracted features.

This project demonstrates how machine learning can be applied to basic source-code analysis.

##  Objectives

- Analyze basic structural features of Python code.
- Extract features such as loop count, nesting depth, recursion, and selected logarithmic-operation indicators.
- Train a machine-learning model using Scikit-learn.
- Predict a time-complexity category.
- Display results through an interactive web application.
- Explore how AI can support algorithm analysis and software development.

##  Features

-  Random Forest classification model
-  Python code input interface
-  Basic source-code feature extraction using Python AST
-  Display of extracted features
-  Real-time prediction after entering code
-  Basic handling of invalid Python syntax
-  Interactive Streamlit dashboard

## 🧪 Example Usage

### Example 1: Constant-Time Operations

```python
a = 10
b = 20
print(a + b)
```

Expected theoretical complexity: **O(1)**, assuming fixed-size integer operations.

### Example 2: Single Loop

```python
for i in range(n):
    print(i)
```

Expected theoretical complexity: **O(n)**, assuming the loop executes \(n\) times.

### Example 3: Nested Loops

```python
for i in range(n):
    for j in range(n):
        print(i, j)
```

Expected theoretical complexity: **O(n²)**, assuming both loops execute \(n\) times.

**Important:** These are theoretical examples. The current prototype learns from synthetic, rule-generated labels and simple code features. Its predictions are not guaranteed to match the actual complexity of arbitrary programs.

##  Machine-Learning Workflow

1. Generate an initial demonstration dataset.
2. Separate input features from target labels.
3. Split the dataset into training and testing sets.
4. Train a Random Forest classifier.
5. Evaluate the model on held-out synthetic examples.
6. Save the trained model using Joblib.
7. Load the model in the Streamlit application.
8. Extract features from user-provided Python code.
9. Display the predicted category and extracted features.

##  Model Evaluation

The training script reports accuracy, precision, recall, and F1-score.

Because the initial dataset is generated from predefined rules, these metrics measure how well the model reproduces those rules. They do **not** establish real-world accuracy in predicting algorithm complexity.

Future evaluation should use independently labeled code samples and verified theoretical complexities.

##  Limitations

- The current prototype analyzes only basic structural features.
- It does not fully understand program semantics or input-dependent execution paths.
- Recursion and logarithmic behavior are not reliably analyzed.
- The predicted category may be incorrect even when the input code is valid.
- The generated dataset is intended for demonstrating the ML workflow, not for validating a production-grade complexity analyzer.
